# Smart Clinic — единое приложение клиники

Три раздела на одном адресе, один код, общий дизайн:

| Вкладка | Адрес | Что это | Папка |
|---|---|---|---|
| Дашборд | `#/dashboard` | AI-дашборд директора: помещения, безопасность, камеры, аналитика, отчёты, AI-ассистент (бывший `ai-clinic-dashboard`) | `src/modules/dashboard` |
| Склад | `#/sklad` | Учёт расходников: приход/расход по сканеру, остатки, заказ поставщикам, Telegram-бот (бывший `clinic-inventory`) | `src/modules/inventory` |
| Разговоры | `#/razgovory` | Качество приёма: разбор разговоров врач–пациент по чек-листу (бывший `clinic-visit-quality`) | `src/modules/transcripts` |

Без адреса открывается дашборд. Авторизации пока нет — все разделы открыты. Данные демонстрационные (в памяти браузера, после перезагрузки сбрасываются).

## Запуск

```bash
npm install
npm run dev            # http://localhost:5173
npm run build          # сборка в dist/
npm run build:single   # один самодостаточный dist/index.html (для заливки на сервер)
```

Стек: React 19, TypeScript, Tailwind 3, Recharts, Framer Motion, Lucide, Vite. У всех трёх разделов он был одинаковым, поэтому зависимости и дизайн-токены общие.

## Как устроено

```
src/
  main.tsx            точка входа
  index.css           общие стили и дизайн-токены (один раз на всё приложение)
  shell/
    Shell.tsx         общая верхняя панель с вкладками + монтирование разделов
    modules.ts        РЕЕСТР разделов: id, подпись, иконка, компонент
  modules/
    dashboard/        дашборд
    inventory/        склад
    transcripts/      разговоры
```

- **Адреса.** `#/<раздел>/<страница внутри раздела>`, например `#/sklad/orders`. Работают прямые ссылки и кнопки «назад» / «вперёд».
- **Раздел = самостоятельное приложение.** Модуль отдаёт default-компонент со своими провайдерами и внутренним роутингом. Оболочка передаёт ему `active: boolean`.
- **Открытые разделы остаются в памяти** (скрытыми): остатки склада, выбранный приём, включённая тревога дашборда не сбрасываются при переключении вкладок. Поэтому всё глобальное в модуле (слушатель сканера, реакция на адрес) должно работать только при `active`.
- **Общая панель** занимает `--shell-h` (3rem, задан в `index.css`). Липкие шапки и сайдбары внутри разделов смещены на эту высоту: `sticky top-[var(--shell-h)]`, высоты на весь экран — `calc(100vh - var(--shell-h))`.

## Добавить раздел

1. Положить приложение в `src/modules/<папка>/` с default-компонентом `App({ active })`.
2. Страницу внутри раздела хранить в адресе `#/<id>/<страница>` — по образцу `parseHash` / `writeHash` в `modules/inventory/App.tsx`: при `active` читать адрес, при переходе писать через `history.replaceState`.
3. Липкие шапки сдвинуть на `top-[var(--shell-h)]`.
4. Добавить запись в `src/shell/modules.ts` (и `ModuleId`).

## Деплой

```bash
npm run build:single
scp dist/index.html root@<сервер>:/var/www/<домен>/index.html
```

Один html-файл, nginx отдаёт его как статику (`try_files $uri $uri/ =404`), роутинг на хэшах, серверных правил не нужно.

## Дальше (пока не сделано)

Логины и права доступа: у директора — все разделы, у администратора — только «Разговоры», у старшей медсестры — только «Склад», директор сам выдаёт права в настройках.

- **Бэкенд** (FastAPI + Postgres): таблицы `users` и `permissions (user_id, module, level)`, вход по логину и паролю, JWT. Проверка прав на каждом маршруте API — скрыть вкладку недостаточно.
- **Фронтенд:** одно место — `shell/modules.ts`. Список `MODULES` фильтруется по правам пользователя, адрес закрытого раздела ведёт на первый доступный.
- **Настройки директора:** таблица «сотрудники × разделы» с уровнем доступа в ячейках, пишет в `permissions`.
