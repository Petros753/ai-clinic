# AI Clinic

Единое приложение для стоматологической клиники: три раздела на одном адресе, один код. Разработчик — Пётр (petr-ai.ru), общение и комментарии на русском.

## Текущее состояние

Работающая **демо-версия фронтенда** в `frontend/`, данные демонстрационные (в памяти браузера). Есть **бэкенд** в `backend/` (FastAPI + Postgres + Alembic, `docker compose`: db, api, web+nginx): вход по JWT, сотрудники и права, склад на API (`/api/stock`); подробности — `backend/README.md`. Дашборд и «Разговоры» пока на демо-данных. Однофайловая сборка (`build:single`) — демо-режим без входа и бэкенда. Демо опубликовано как один html-файл на https://sklad.petr-ai.ru (nginx на VPS 217.26.31.135, `scp` одного `index.html`).

| Раздел | Адрес | Папка | Что это |
|---|---|---|---|
| Дашборд | `#/dashboard` | `frontend/src/modules/dashboard` | AI-дашборд директора: интерактивный 3D-план клиники со слоями (температура, CO₂, влажность, занятость), безопасность, камеры, аналитика, отчёты, AI-ассистент |
| Склад | `#/sklad` | `frontend/src/modules/inventory` | Учёт расходников: приход/расход сканером штрихкодов, остатки, заказ поставщикам, Telegram-бот |
| Разговоры | `#/razgovory` | `frontend/src/modules/transcripts` | Качество приёма: разбор разговоров врач–пациент по чек-листу |

Подробности устройства и запуска — `frontend/README.md`.

## Стек фронтенда

React 19, TypeScript, Tailwind 3, Recharts, Framer Motion, Lucide, Vite. Сборка одним файлом: `npm run build:single` (vite-plugin-singlefile).

Запуск: `cd frontend && npm install && npm run dev`.

## Архитектурные правила (важно не сломать)

- Оболочка `frontend/src/shell/` рисует общую верхнюю панель и монтирует разделы из реестра `shell/modules.ts`. Раздел — самостоятельное приложение с default-компонентом `App({ active })`.
- Адреса: `#/<раздел>/<страница>`. Раздел пишет адрес через `history.replaceState` и читает его только при `active`.
- Открытые разделы остаются в памяти (скрытыми, `hidden`). Поэтому всё глобальное в разделе (слушатель сканера, реакция на `hashchange`) работает **только при `active`**, иначе скрытый раздел перехватывает чужие события.
- Липкие шапки и сайдбары внутри разделов сдвинуты на высоту общей панели: `top-[var(--shell-h)]`, `calc(100vh_-_var(--shell-h))` (в Tailwind подчёркивания вокруг операторов).
- Вход и права: `shell/auth.tsx` (`useAuth`, `useUser`, флаг `DEMO`), запросы в API — только через `apiFetch` из `shell/api.ts` (подставляет токен, на 401 выкидывает на вход). На бэкенде маршруты раздела — через `module_router("<раздел>")`, изменения — `dependencies=[edit("<раздел>")]` (`backend/api/app/deps.py`); тест `test_routes_protected.py` ловит маршрут без проверки.
- Склад: данные — только через `useData()` (`inventory/context/DataContext.tsx`), там два режима: демо в памяти и API с очередью операций (`lib/queue.ts`). Справочники (категории, поставщики, кабинеты, сотрудники) — из `inventory/data/catalog.ts`, не из `mock.ts`. На сервере остаток меняется только через `apply_operation` (`backend/api/app/stock.py`).
- План клиники: SVG `viewBox 0 0 1447 1087` поверх `dashboard/assets/clinic-plan.webp`. Комнаты — полигоны `shape` и точки `labelAt` в `dashboard/data/mock.ts` в пикселях картинки. Название комнаты показывается только при наведении, на плане значки слоя.

2. ~~**Пользователи и роли.**~~ Сделано. Вход по логину и паролю, JWT, таблицы `users` и `permissions (user_id, module, level)`. Директор видит всё, администратор только «Разговоры», старшая медсестра только «Склад». Директор выдаёт права в настройках (таблица «сотрудники × разделы»). Права проверяются **на каждом маршруте API**, скрыть вкладку недостаточно. На фронте список `MODULES` фильтруется по правам.
3. ~~**Склад.**~~ Сделано, кроме Telegram-бота (страница «Telegram-бот» пока превью). Заменить демо-данные в памяти слоем API: `POST /api/stock/movements` (`type`, `items: [{barcode, qty}]`, `user`, `idempotency_key`), остатки считает сервер. Сканер работает как клавиатура (HID), слушатель уже есть. Непроведённые сканы копить в очереди в браузере при обрыве сети. Telegram-бот пишет в тот же API.
4. **Разговоры.** Загрузка аудио, транскрибация, разбор по чек-листу. Открытые вопросы: где считать ИИ (API или своя GPU), согласие на запись.
5. **Дашборд на живых данных.** Датчики (температура, CO₂, влажность) и камеры; зависит от оборудования, которое ставят электрики.
